# Tabular regression

**Status:** active
**Owner:** DCLab R&D · **Started:** 2026-10-15

## Research question

How does DCLab predict a number from one table (minutes, a price, an amount) without a post-outcome column in it, and how much does a wrong split or a kept leak flatter the error? The answer decides which columns the regression kind keeps out and which split it reports.

## Why it matters for DCLab

The `regression` kind (`dclab_rnd/kinds/regression.py`) runs in the engine from this track's evidence: its acceptance on the delivery-time replica (campaign `kinds_v1`), its pitfalls on the replica (`pitfalls_by_kind_v1`) and the benchmark's regression cases (`benchmark_v4`). Before 16.14 the kind pointed at the forecasting track, which is about series, not one number per row.

## Prediction contract

For modeling work, write this before looking at any score (rule DCLAB-R01):

| Item | Value |
|---|---|
| Unit of prediction | one row of the table (an order, a listing) |
| Prediction moment | when the row is created, before its outcome |
| Target and window | the number the row's outcome takes (the delivery's minutes) |
| Allowed information | what exists when the row is created |
| Forbidden information | the outcome's own time or rating (delivered_at, courier_rating), anything written after |
| Primary metric | MAE, with the training median as the baseline |

## Result schema

Write results in the shape the rest of the repository already understands, so `dclab_rnd.evidence_index` can index them and the SFT builder can learn from them:

```json
{
  "schema_version": 1,
  "campaign_id": "tabular_regression_v1",
  "experiment_id": "TRG-001",
  "dataset": "dataset_key",
  "kind": "data_understanding | leakage_audit | feature_engineering | model_selection | optimization_reliability",
  "task_type": "binary | multiclass | regression | timeseries_regression | graph_node_classification | ...",
  "primary_metric": "roc_auc | average_precision | macro_f1 | mae | ...",
  "question": "...",
  "hypothesis": "...",
  "setup_summary": "1-3 sentences: exactly what was compared, with numbers",
  "evidence": {"selection_rule": "...", "...": "..."},
  "claims": [{"claim_id": "TRG-001-C1", "kind": "fact | risk | decision | recommendation",
              "statement": "...", "evidence": ["evidence.<key>"], "limitations": ["..."]}],
  "provenance": "from dclab_rnd.provenance.capture_provenance(...)"
}
```

Results that follow the five standard stages can live under `evidence/campaigns/<track>_v1/results/EXP-*.json`, where the evidence index, the critic gate and the SFT builder pick them up automatically.

## Conclusions
