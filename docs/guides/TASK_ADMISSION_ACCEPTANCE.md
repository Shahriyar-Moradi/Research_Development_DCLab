## 1. Problem and Boundary

Previously, `TaskDispatcher._sources` strictly enforced `fresh == graph` against the deterministic baseline generated by `adapt_workflow`. While TP-02 successfully decomposed problems into valid model hierarchies with model provenance (`method='model'`), the runtime was unable to admit or execute them.

This package implements strict, reviewed admission of model-proposed task hierarchies while preserving all existing physical safety guarantees:
- **No parallel engine or dispatcher:** `TaskDispatcher` and `SolutionTeam` remain the sole execution authorities.
- **Double opt-in:** Task execution requires `enabled=True`, and proposed hierarchy admission requires an explicit `admit_proposals=True`. The default remains `False`.
- **Zero modification of atomic physical tasks:** The non-group leaves (`data`, `leakage`, `features`, `models`, `holdout`, `final`, `report`), their required capabilities, input/output artifact bindings, and deterministic acceptance checks are immutable and must match the baseline exactly.
- **Strictly constrained model degrees of freedom:** The model may only introduce grouping nodes and add topological dependencies that preserve all mandatory baseline dependencies.
- **Immutable single holdout gate:** The human holdout gate cannot be bypassed, reordered after final evaluation, or approved by a model.
- **Deterministic fallback:** Any malformed, invalid, tampered, or stale proposal is refused with zero effects and preserves the deterministic workflow fallback.

## 2. Implementation Architecture

### 2.1 Admission API (`TaskDispatcher.admit`)

```python
d = TaskDispatcher(store, saver, enabled=True, admit_proposals=True)
result = d.admit(project_id, candidate_graph)
```

1. **Pre-execution Check:** Admission is permitted only before execution begins (no recorded attempts or transitions). Once work starts, the graph cannot be swapped.
2. **Baseline Reconciliation:** The dispatcher compiles a fresh baseline using `adapt_workflow`.
3. **Candidate Validation:**
   - Candidate must be a valid `TaskGraph` with `provenance.method == 'model'` and `revision == baseline.revision + 1`.
   - Structural equality on all non-group leaves (`_atomic_specs(candidate) == _atomic_specs(baseline)`).
   - Mandatory dependencies from baseline must be present in the transitive dependency closure of each candidate leaf.
   - Bounded hierarchy: node count $\le 32$, depth $\le 4$, acyclic parent references rooted at `'root'`. All group nodes except `'root'` must descend from `'root'`. All leaf nodes must have valid group parents connected to `'root'`.
   - Contractual graph validation: `validate_graph(candidate, workflow, ...)` returns no errors.
4. **Durable Admission Receipt:** Checkpoint state records an immutable admission receipt containing the candidate fingerprint, producer version, and reference ID.

### 2.2 Re-validation at Execution Time (`_sources`)

Before any stage execution, crash recovery, or verification step, `_sources` re-validates the graph:
- If `method == 'deterministic'`, verifies `baseline == graph`.
- If `method == 'model'`, runs `_validate_admitted_graph`:
  - Re-checks that `state['admission']['fingerprint'] == graph.fingerprint`.
  - Verifies that `graph.provenance.method == 'model'` and that `reference_id` and `producer_version` match `state['admission']` exactly.
  - Verifies that current project inputs, problem brief, and capabilities still match the source references.
  - Verifies that no leaf authority, acceptance check, or mandatory dependency was altered.
- In `dispatch()`, if `graph.provenance.method == 'model'` and `not self.admit_proposals`, raises `Blocked("proposed_graph_admission_disabled")` before any tool call or attempt registration.

### 2.3 Preserving Model Structure Across Source Updates (`adopt_sources`)

When human confirmation updates project sources (e.g., clarified prediction moment):
- `adopt_sources` compiles the updated deterministic baseline.
- If the current graph was an admitted model proposal, it re-grounds the model's group structure and dependency edges onto the updated baseline leaves, advancing the graph revision and updating the admission receipt.
- The reconstructed graph is validated against `_validate_admitted_graph` before updating state; any invalid or dangling structure causes a clean refusal.
- Stale attempts are invalidated without discarding the admitted structure.
