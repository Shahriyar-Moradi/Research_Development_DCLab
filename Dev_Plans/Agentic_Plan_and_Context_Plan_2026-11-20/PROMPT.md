# Coding prompt for Agentic Plan and Context Plan

Use the text below as the task for a coding model working in this repository. Default starting package: **A1**. On continuation, supply the last accepted package and its check results.

---

Implement one complete package of the November 20 Agentic Plan and Context Plan in DCLab R&D. Read the root AGENTS.md, [product plan](PLAN.md), and the selected section of the [implementation plan](IMPLEMENTATION_PLAN.md). Use the normal product path and the smallest relevant fixture. Work in English. Preserve unrelated local changes.

1. **Select the slice.** If no handoff identifies a package, start with A1. Otherwise confirm the preceding package exists at the normal entry point and select the first unfinished dependency. State the visible behavior, starting function, affected guard, and acceptance checks before editing. Treat function or schema names proposed in the plan as design guidance. Follow the current checkout if an equivalent capability exists.
2. **Establish the baseline.** Trace one real request. Read the closest test and its fixture. Record current behavior with an invented case. For A1, use delivery ETA with and without a confirmed prediction time. Extend the existing Lead and registered tools. Keep memory schema changes for A3 or later.
3. **Implement and exercise the selected behavior.** Add a focused failing case for the missing behavior, wire the smallest change through its caller, and make it pass. Include one rejection or retry case from the package. Use the current harness, permission checks, gateway, event records, storage and UI conventions. For model decisions use scripted responses during implementation. For writes validate scope and version immediately before the effect. Never use a model to choose a split, bypass a workflow approval, or independently inspect a final holdout.
4. **For memory packages**, verify scope on read, search, edit, summarize, resume and worker execution wherever this slice reaches. Test a permitted read and a sibling or private fact that must be absent. Preserve source identity, revisions and legacy data. Record corrections and invalidate previously derived advice. Keep project facts editable by authorized project members and personal facts private. Do not copy raw model exchanges into product memory.
5. **Check the actual caller.** Use the checkout's targeted test runner, for example `.venv/bin/python tests/run_parallel.py test_case_agent test_case_home` for A1 when both files are affected. Select different files for other packages. Follow the standing owner instruction on test scope. Use authored sources and rebuild only affected generated assets or contracts by their established commands. No credentials, paid model calls, sealed evaluations, or training are required for a development slice.
6. **Hand off.** Report package and revision, changed behavior, entry point, changed files, exact checks and outcomes, compatibility and rollback, remaining evidence and the next package ID. State whether the feature is available through Home, Lead or Advisor and whether its new switch is on. Keep live promotion pending until its own evidence exists.

For A1 the observable output is one trace where a missing prediction time causes a clarification, another where a known time permits inspection, and one refusal or stop with no unintended effect. Once those pass through the actual caller, hand off A2. For later packages use their explicit “Done when” conditions. If a dependency genuinely cannot be satisfied, finish independent checks and identify the specific missing prerequisite.
